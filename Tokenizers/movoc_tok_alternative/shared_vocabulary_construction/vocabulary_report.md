# MoVoC Vocabulary Composition Report

Generated by `scripts/build_movoc_vocab.py` following MoVoC Algorithm 1
(paper Sec. 3.2, arXiv:2509.08812).

**Note on figures.** Two kinds of number appear in this report and are kept
distinct throughout: the *published algorithm and its parameters*, cited to the
paper; and *artifact-derived reference values* read from released
configuration files, which are not attributed to the paper text. See §1.

---

## 1. Parameter allocation (Step 2)

### Published Algorithm 1 (cited)

The allocation procedure and its parameters are stated in the MoVoC paper,
Sec. 3.2 / Algorithm 1 (arXiv:2509.08812), and reproduced in the released
repository README:

```
V = V_BPEsmall ∪ V_morph
|V_BPEsmall| = s(1 − r)        |V_morph| = sr
```

with `s = 224000` and `r = 0.7142857142857143` given as the invocation
parameters. These are the values used here:

```
s          = 224,000
r          = 0.7142857142857143      (5/7)
N          = 2                       (Amharic, Tigrinya)

s_lang     = s / N          = 112,000
s_BPE      = s_lang (1 − r) =  32,000
s_morpheme = s_lang × r     =  80,000
```

These reproduce the allocation recorded in the released
`configs/movoc_config.json` exactly (`s_lang: 112000`, `s_bpe: 32000`,
`s_morpheme: 80000`). `s_BPE = 32,000` matches the independently trained BPE
tokenizers, so no retraining was required.

### Artifact-derived reference values (not cited from the paper text)

The released `configs/movoc_config.json` additionally records the *outcome* of
the original run:

```
v_morpheme_amharic:  50,978
v_morpheme_tigrinya:  7,125
v_movoc:            114,553
```

**These are artifact-derived reference values, not figures quoted from the
paper.** They were located only in that configuration file; they do not appear
in the paper-citing documentation available here, and no section, table or page
reference for them could be established. They are used below solely as a
comparison point against a prior run of the same pipeline, and must not be represented as published results.

## 4. Reconstruction result vs. the artifact-derived reference value

This reconstruction produced **105,310** entries. The released configuration
artifact records **114,553** for the original run (see §1 — an artifact-derived
value, not a paper citation).

The difference is entirely attributable to **morpheme availability**, not to a
deviation in the algorithm. Three distinct quantities must be separated:

**a. Theoretical allocation.** Algorithm 1 allocates `s_morpheme = 80,000`
morphemes per language, or 160,000 across both. This is an *upper bound* on
how many morphemes may enter the vocabulary — it is a budget, not a guarantee
that this many exist.

**b. Actual unique morphemes available.** After exhaustive extraction from
the HornMorpho segmentation datasets and full supplementation from the
official MoVoC annotations, only 44,104 (Amharic) and 8,793 (Tigrinya) unique
morphemes exist — 52,897 in total, against a budget of 160,000. The step
"select the top `s_morpheme` morphemes" therefore selects everything
available, because a set smaller than *k* has no top-*k* subset other than
itself.

The released configuration artifact records `v_morpheme_amharic: 50,978` and
`v_morpheme_tigrinya: 7,125` for the original run. Our Tigrinya figure (8,793)
slightly exceeds that value; our Amharic figure (44,104) falls 6,874 short. The most likely cause
is corpus scale: the morphological analysis here ran over the HornMT corpus
(2,030 sentences, ~14,000 unique words per language), whereas a larger
analysis pass would surface more morpheme types. This is a property of the
input data, not of the merge.

**c. Duplicate removal in the union.** 11,587 tokens were contributed more
than once and counted a single time, as Step 5 requires.

**Reconciliation:**

```
  32,000  Amharic BPE          (allocation filled exactly)
+ 32,000  Tigrinya BPE         (allocation filled exactly)
+ 44,104  Amharic morphemes    (80,000 allocated, 44,104 available)
+  8,793  Tigrinya morphemes   (80,000 allocated,  8,793 available)
─────────
 116,897  contributed
− 11,587  duplicates removed
─────────
 105,310  final unique vocabulary
```

Had the full morpheme budget been fillable, the vocabulary would approach the
theoretical maximum of 224,000 before deduplication. The artifact-derived
114,553 likewise falls well short of 224,000, indicating that the original run
also exhausted its morpheme resources — the two runs differ in *how much*
morpheme material was available, not in how the algorithm was applied.

## 5. Exhaustion verification

Confirmed by independent recount, separate from the build script:

* **HornMorpho datasets** — Amharic: 10,293 records → 2,731 unique morphemes
  (25,022 instances). Tigrinya: 6,692 records → 2,223 unique morphemes
  (14,903 instances). **Zero** non-placeholder fields were left unextracted in
  either dataset.
* **Annotation datasets** — Amharic: 153,759 records → 42,897 unique
  morphemes. Tigrinya: 7,531 records → 7,127 unique morphemes. Fields that
  produced no morpheme were verified to contain only the literal placeholders
  `-` and `--` (121 Amharic, 12,173 Tigrinya), i.e. genuinely empty slots.
* **No remaining sources.** The other released annotation files are
  deliberately excluded: `tigrinya/gold_morphemes.json` (206 entries) is held
  out for evaluation per the paper, and `geez/` and `tigre/` are not
  Algorithm 1 languages in this two-language construction.

## 6. Reproducibility

The pipeline is deterministic. Rebuilding from identical inputs produces
byte-identical output:

```
movoc_vocab.txt   md5=023337121729f8cab0493df0d9bd05d7   IDENTICAL on rebuild
movoc_vocab.json  md5=8969507a84d18f6f2926e179bd9fbe3e   IDENTICAL on rebuild
```

Determinism holds because frequency ranking breaks ties on the morpheme string
itself, BPE vocabularies are read in the model's native piece order, and the
union iterates languages in a fixed order.

### Environment

| Component | Version |
|---|---|
| HornMorpho | 5.3.6 |
| HornMorpho Amharic grammar | `a.lg` v1.6 |
| HornMorpho Tigrinya grammar | `t.lg` |
| SentencePiece | 0.2.1 |
| Python | 3.13 |

A researcher with the same HornMorpho version and HornMT resources, the same
NLLB corpora, and the same MoVoC annotation files will reproduce this
vocabulary exactly by running:

```bash
python scripts/build_morpheme_json.py <corpus> --language am -o <out>.json
python scripts/train_bpe.py <NLLB corpus> --lang Amharic --outdir tokenizers/amharic_bpe_32k
python scripts/build_movoc_vocab.py --outdir movoc
```

One caveat on end-to-end reproducibility: the BPE step samples 5,000,000
sentences from the 16.1M-sentence Amharic corpus with
`shuffle_input_sentence=True`. SentencePiece seeds this internally, and the
resulting model is fixed and checksummed above — so the vocabulary is
reproducible from the *released tokenizer*, which is what this pipeline
consumes. Retraining BPE from raw corpora on a different SentencePiece build
could yield a slightly different sample.
