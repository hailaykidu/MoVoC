# Results — original paper vs. Version 2 reconstruction

This directory is an **archival and documentation layer**. It exists so that
the published paper's results and this repository's reconstructed results
can coexist without ambiguity.

Nothing here is a working path. Scripts read from and write to the original
locations (`evaluation/results/`, `experiments/multiseed/results/`); the
files below are **copies**, preserved under explicit names.

```
results/
├── original_paper/          documentation only — no result files exist
└── reconstruction_v2/
    ├── intrinsic/           copies of reconstructed intrinsic results
    └── mt/                  copy of the reconstructed multi-seed MT results
```

## The distinction in one paragraph

The **original paper results** are the values printed in the publication.
They are cited in the top-level [`README.md`](../README.md) §1 and in the
paper itself. The checkpoints, predictions and scoring pipeline that
produced them were not recovered, so **no original result file exists in
this repository** — see [`original_paper/README.md`](original_paper/README.md).

The **Version 2 reconstruction results** were generated by the current
reimplemented code, from newly trained checkpoints, scored by a
reconstructed evaluation pipeline. They are new measurements. They are not
corrected, updated or verified versions of the published numbers, and they
may differ from them — see
[`reconstruction_v2/README.md`](reconstruction_v2/README.md).

**The two sets must never be merged into a single table or compared
directly.** The reasons are set out in
[`../docs/reconstruction_vs_original.md`](../docs/reconstruction_vs_original.md).

Each copy is byte-identical to its source.

> **Note on `paper_tables.json`.** Despite the name, this file contains
> *reconstructed* values in the paper's table **layout** — it is not the
> paper's reported data. The file's own `not_a_reproduction` field states
> this. The name is retained because scripts and existing documentation
> reference it; the copy here carries the explicit `_reconstruction_v2`
> suffix.
